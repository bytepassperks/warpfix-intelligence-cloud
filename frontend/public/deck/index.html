The problem

CI breaks. Engineers become log readers.

  • Every red run is a context switch. Read the logs, reproduce locally, guess a fix, push, wait for CI again.
  • Review tools comment; they don’t repair. CodeRabbit, Snyk and friends tell you what is wrong — the pipeline stays broken.
  • The same failures repeat across repos. Flaky tests, dependency breaks and type errors are re-diagnosed from scratch every time.
CI repair is the missing half of the developer toolchain: review tools surface problems — nothing closes the loop back to a green pipeline.

Fingerprint learning

Each error is normalized and hashed. When the pattern returns, the proven fix is reused instantly — no LLM call, no wait.

Deterministic first

Lint, format and import fixes run through ESLint, Prettier and Ruff at zero LLM cost. AI is reserved for non-trivial repairs.

Why Daytona

Every patch has to earn its PR in a clean sandbox.

  • One sandbox per repair. Fresh container, install the project’s dependencies, run the failing suite, compare results, tear it down — 30 to 180 seconds, bursty and parallel.
  • Today this is our bottleneck. Validation runs on a single 512 MB worker; JVM and large Maven/Gradle builds OOM mid-run, so verified repairs for those ecosystems are switched off.
  • What we need: fast cold starts, per-second billing, snapshot restore for warmed dependency caches, and the ability to burst to dozens of concurrent short-lived sandboxes.
Daytona’s sub-90 ms sandbox creation and snapshot model fit this workload exactly — validate every patch, on every stack, without pre-warming a fleet.
